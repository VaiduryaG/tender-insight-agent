## 一、目标与范围

| 项 | V1.0 现状 | V2.0 目标 |
|----|-----------|-----------|
| 数据量 | 18 条（人工采集） | **500+ 条**（自动化爬取，稳定后可加量） |
| 数据源 | 中国政府采购网 | 同左（做深不铺开） |
| 公告类型 | 中标公告 | 同左（schema 不变） |
| 字段获取 | 人工摘录 | 网页正文自动提取；附件/PDF 金额提取 = P1（下期） |

**明确不做**：PDF 扫描件 OCR（P2）、跨平台数据源（P2）、定时调度（V2.1）。

## 二、合规与风险控制（最高优先级）

### 2.1 合规依据
- 中标公告是政府主动公开信息，robots 协议不禁止，爬取公开数据合法合规
- 以学习研究为目的、低频访问、不碰批量接口、不绕过任何鉴权

### 2.2 访问节奏（保守参数，已与作者确认）

```
请求间隔：    5-8 秒随机（模拟人阅读节奏）
连续休息：    每爬 10 页暂停 60-120 秒
单日上限：    200 个请求
时段限制：    仅工作日白天运行（网站维护窗口避开深夜）
总预期耗时：  500 条详情 ≈ 2-3 小时，可分多天完成
```

### 2.3 风险应对

| 风险 | 触发条件 | 应对 |
|------|----------|------|
| 限流（429） | 短时频率过高 | 立即停止 → 冷却 30 分钟 → 间隔加倍后继续 |
| 封禁（403） | 触发 WAF | **立即停止当日爬取**，冷却 24h；重启时间隔加倍 |
| 连续解析失败 | 页面结构变更 | 连续 5 条解析失败自动停止，人工检查页面结构 |
| 公司网络告警 | 流量异常 | 低频+限量已规避；不用公司网络跑任何压测 |

**红线**：任何情况下不使用并发请求；不重试被 403 拒绝的 URL（当日）。

## 三、数据源分析（中国政府采购网）

```
列表页：  www.ccgp.gov.cn/cggg/dfgg/zbgg/index.htm     （地方公告-中标公告）
分页：    index_1.htm, index_2.htm, ...
详情页：  /cggg/dfgg/zbgg/202609/t20260908_27288986.htm
```

- 静态 HTML，`requests + BeautifulSoup` 覆盖（DrissionPage 留作备选）
- 按栏目分页顺序爬，**不用站内搜索**（搜索接口反爬严，绕开）
- D1 技术验证产出《HTML 结构笔记》后再写代码

## 四、模块划分

```
src/crawler/
├── base.py        # Session管理、UA池、随机延时(5-8s)、限速器、指数退避重试、连续失败熔断
├── ccgp.py        # CcgpCrawler：列表页翻页 → 详情URL队列（增量过滤）→ 详情页抓取
├── parser.py      # HtmlParser：详情页HTML → 正文纯文本（去导航/页眉/脚本）
├── extract.py     # FieldExtractor：正文提取 中标供应商/金额/采购人/编号/日期（规则模板库，记录命中模板）
└── storage.py     # RawStore：JSONL 原文存储 + seen_urls.json 增量去重 + 断点续爬

scripts/
├── crawl_ccgp.py  # 爬取入口：--pages N，内置单日请求上限
└── parse_raw.py   # 原始JSONL → V1.0 schema 12列CSV → 衔接 run_stage1
```

**设计决策：**
1. **原文落地 JSONL**（`data/raw/crawled/*.jsonl`）：解析规则必迭代，留原文可重解析不重爬
2. **爬取与解析分离**：爬取只存原文（最小化在线时间），解析纯本地可反复跑
3. **Schema 对齐**：输出与 bidding_sample.csv 相同 12 列，无缝衔接现有管线
4. **增量**：seen_urls.json 记录已爬 URL；解析后按 project_id + 标题相似二次去重

## 五、数据清洗强化

### 5.1 正文结构化提取（extract.py，工作量最大）
- 每字段多套正则模板按优先级尝试，记录命中模板（质量分析用）
- 提取失败 → 留空 + `needs_review` 标记，**不猜测，宁缺勿错**
- 验收：供应商/金额/日期提取准确率 ≥90%（人工抽检50条）

### 5.2 实体对齐增强
- 500+ 数据量下 L2 模糊阈值（现 0.82）用真实数据重新标定
- **打开 L3 LLM 复核**（灰区量级预计几十次，免费额度内）
- 映射表工作流：低置信度 → needs_review 清单 → 人工确认 → 回写映射表 → L4 命中

### 5.3 去重强化
- 标题归一化 + SimHash 相似去重（同公告多栏目收录）
- project_id 格式归一化后再比对

### 5.4 质量评估体系
- stage1_report 升级：字段完整率、各模板命中率、对齐置信度分布、needs_review 数量
- 人工标注 50 条基准集，清洗策略改动跑基准对比

### D1 技术验证结论（2026-09-16，共4个请求）

| 验证项 | 结果 |
|--------|------|
| robots.txt | 不存在（404），无协议约束；裸 curl（无浏览器头）被 WAF 拦截（403+拦截页，暴露公司出口IP） |
| WAF 特性 | 对请求头特征敏感：**带完整浏览器 UA 后一切正常**（robots 404 到达真实服务器 / 列表 200 / 详情 200） |
| 列表页结构 | 静态 HTML；详情链接 `./202609/tXXX.htm` 相对路径，每页约20条；**`<li>` 自带发布时间/地域/采购人元数据**（列表页即可获取，减少详情解析依赖） |
| 分页机制 | JS `Pager({size:25, current:0, prefix:'index', suffix:'htm'})` → `index.htm`/`index_1.htm`/... |
| 详情页结构 | 正文容器 `div.vF_detail_main`；中标（成交）金额（元）/采购人/项目编号 均在正文，可规则提取；金额为表格布局带大量空白，extract 模板需处理 |
| 技术栈结论 | **requests + BeautifulSoup 足够，DrissionPage 不需要**；必须带完整浏览器请求头（UA/Accept/Accept-Language/Referer） |

**试探纪律执行记录**：4 个请求、间隔 6-10 秒、无并发，全程无封禁迹象。
